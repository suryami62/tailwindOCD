Extension Playground

Tailwind OCD feature torture test.

Open this file in a Tailwind-enabled project, run Tailwind OCD: Sort Tailwind Classes in Current File, then save it again to confirm sort-on-save. Every example below is intentionally messy so you can verify sorting, duplicate cleanup, conflict cleanup, dynamic function scanning, the ignore marker, and custom regex support.

What to Check

Expected behavior

  • Utility order should follow Tailwind CSS IntelliSense sorting.
  • Duplicate classes should collapse to the last occurrence.
  • Simple conflicts like p-2 p-6 should keep the last one.
  • Variant scopes like md: and hover: should be respected.
  • Lines containing tailwindocd-ignore should remain untouched.
  • Strings inside clsx(), cn(), and classnames() should be processed.
  • Multiline values and variant-heavy utility strings should stay semantically intact.
  • Custom regex samples should only react after you enable the matching workspace setting.
Settings

{

With that setting enabled, the Twig-like sample at the bottom of this file becomes sortable too.

Run Order

Suggested experiment flow

  1. Run the command once and inspect which blocks changed.
  2. Undo, disable cleanDuplicates, run again, and compare the diff.
  3. Undo, enable duplicates cleanup and disable cleanConflicts, then rerun.
  4. Save the file to confirm sortOnSave only affects supported matches.
  5. Enable customClassRegex and rerun to activate the Twig and helper samples.

Dynamic Functions

Quoted strings inside clsx, cn, and classnames

<script type="module">
  const isPrimary = true;
  const isOpen = false;
  const clsx = (...parts) => parts.filter(Boolean).join(" ");
  const cn = clsx;
  const classnames = clsx;

  const buttonClasses = clsx(
    "rounded-md bg-orange-500 px-2 px-5 text-white text-white block inline-flex",
    isPrimary && "font-bold font-light hover:text-zinc-50",
    isOpen ? "md:p-2 md:p-6" : "p-2 p-4"
  );

  const panelClasses = cn(
    "grid block gap-2 gap-6 rounded-2xl rounded-3xl",
    "md:hover:m-2 md:hover:m-8"
  );

  const badgeClasses = classnames(
    "inline-flex hidden items-center text-left text-right",
    true && "py-1 py-3"
  );

  const nestedClasses = clsx(
    "w-full w-1/2 min-w-40 min-w-80",
    isPrimary && clsx("text-left text-right", "font-medium font-black")
  );

  const customHelperClasses = tw(
    "rounded-xl rounded-none px-2 px-7 bg-white bg-zinc-200"
  );

  console.log({ buttonClasses, panelClasses, badgeClasses, nestedClasses, customHelperClasses });
</script>

tw() is intentionally not part of the default dynamic helper list, so it is useful for testing an updated dynamicClassFunctions config.

Function Config

Optional dynamic helper expansion

{
  "tailwindOCD.dynamicClassFunctions": [
    "clsx",
    "cn",
    "classnames",
    "tw"
  ]
}

Enable this if you want the tw() sample above to participate in sorting too.

Custom Regex

Twig-style sample for customClassRegex

{% set tw_card = "text-white bg-slate-900 px-2 px-6 p-2 p-5 flex hidden md:hover:m-2 md:hover:m-6" %}
{% set tw_banner = "rounded-lg rounded-3xl block inline-flex text-left text-center" %}

tw("bg-white bg-slate-100 px-3 px-7 rounded-2xl rounded-none")
tw("font-light font-bold inline hidden text-left text-right")

The Twig lines are for tuple-style regex. The tw() lines are useful if you want to try a single-pattern custom regex that extracts quoted strings from helper calls.
